# v1.42.1 FINAL CODE MERGE 变更说明

## Identity

`StableIdentityAssigner` 新增 `build_fast_gate()`，门控复用原 `_distance_and_gate()` 的硬拒绝条件，不引入新的距离或体型阈值。被 gate 掉的 pair 在旧 `_cost()` 中本来就是 `INF_COST`。

当前实际配置使用 `KeypointMotionIdentityAssigner`。因此同时在它的 NumPy cost matrix 前加入向量化硬门控：鲁棒体型比例 + 预测中心 hard gate。候选密度低于阈值时进入 `cascade_sparse_numpy`，只对候选 cell 计算关键点、IoU、朝向、体型和置信度项；密集场景保持原 dense NumPy 路径。主程序已把 `performance.identity_cascade` 正确注入每视频 `identity_runtime_cfg`。

## Pair Behavior

v1.41.1 已存在等价的 Frame Behavior Cache 能力，因此没有把 `PairFeatureComputer.compute(actor,target,history)` 机械改成一个新 API。保留现有每帧 history map、trajectory、target-turn、distance-drop cache，并保留 NumPy/多进程 pair 计算路径。这样避免行为判定 API 扰动。

## Mask Trigger

新增 `mask_trigger_controller.py`，由主流程在 `mask_extractor.enrich_frame()` 前决策。上传的 backend 包没有 `mask_cluster_reid.py`，所以没有用不完整的新模块覆盖用户项目原文件。

严格默认模式中，只要 `instance_mask_memory.identity_cost_weight > 0` 或 `cluster_reid.mask_weight > 0`，mask 保持每帧运行。这是结果保持约束。可选 aggressive 模式才会对低风险帧 skip。

## NVENC

`nvenc_video_writer.py` 现在是统一 writer factory。优先 `h264_nvenc`，编码器存在后再做实际硬件 probe；失败回退 OpenCV。主 annotated video、checkpoint 分段视频和分段 merge 已接入。短事件 clip 等次级 writer 保持旧 OpenCV 路径，避免扩大变更面。

## GPU 配置

bundled YAML 使用：

```yaml
model:
  half: true
performance:
  yolo_first_pass:
    batch_size: 4
```

`half: true` 在上传的 v1.41.1 中本来就已启用；本次主要按目标把 first-pass batch 调为 4。batch 大小的真实吞吐必须在目标 RTX3060 Laptop 上 benchmark，不能仅凭 GPU 型号保证 30–50%。

## Regression

- `tests/test_v1421_merge.py`：Mask Trigger 严格/实验模式、NVENC factory、主路径 cascade 配置接线。
- `tests/regression_performance_test.py`：新增 Identity sparse/dense 代价矩阵逐元素完全一致测试，同时保留原 detection/appearance、cluster context、pair feature、SQLite/checkpoint 回归。
- `tests/regression_v1421.py`：用于真实视频输出目录 A/B，检查 Tracking、Behavior、CSV/JSON schema。
