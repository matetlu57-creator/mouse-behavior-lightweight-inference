## 审核方式

1. 对照完整原片和候选裁剪，填写实际行为、目标视觉 ID、起点帧（包含）和终点帧（不包含）。可从当前原片画面设置起点/末帧，使用 0.25/0.5 倍速检查动作。
2. 点击“确认通过并同步”。只有显示“已通过：新数据集与原始四类文件已同步”才表示保存成功。裁剪视频、轨迹、标注与 metadata 一起更新，审核状态落盘，刷新/重启可恢复。
3. “不通过”“暂不确定”不会纳入新数据集。已通过片段可重新修改并确认；“撤回 / 重置为待审核”会撤销对应输出。行为与审核状态筛选可显示未处理片段。
4. 新数据集路径显示在页面顶部；“查看新数据集清单”列出当前通过的来源、标签、视觉 ID、帧范围及同步目标。

## 数据路径与同步规则

- 审阅包：`outputs/behavior_segment_screen_v3/`。原片副本与候选裁剪保留为本批冻结证据，不因人工回写更改。
- 正式新数据集：`outputs/behavior_confirmed_dataset/dataset/<行为>/<review_id>/`。只含本次确认通过的片段，兼容 `discover_samples()`，包括 clip.mp4、tracks.json、annotation.json、metadata.json、review_receipt.json。
- 原文件：`$env:DATASET_ROOT/<行为>/<原样本名>/`。首次确认前将完整原样本目录备份到 `outputs/behavior_confirmed_dataset/backups/<source_key>/sample/`，并记录全部文件 SHA256。备份包括附属文件；四类数据文件同步裁剪，其他文件保留。
- 改行为标签时同步行为父目录，避免标签与目录不一致。一个原片多个窗口通过时保留独立样本；首个主样本使用原样本名，额外窗口使用 `__confirmed__<review_id>` 后缀。如与非本批样本冲突则加来源后缀或拒绝，不覆盖别的样本。
- 主样本撤回后由剩余通过窗口接替；该来源全部撤回后，恢复原目录和完整原片的全部文件字节。所有后续裁剪从不可变备份生成，不会再次裁剪已经缩短的原片。
- 原数据集在审核期间包含“已同步的通过样本”和尚未审核的旧样本；用于训练的新数据集请使用上述 confirmed dataset。否决不会删除未经修改的原片。
- 原始 clip-local 范围 `[start,end)`；输出帧 `0..n-1`，时间 `[0,n/fps)`；metadata.source 保留真实录制偏移。保留视觉 track ID，不推断 RFID/生物身份。

## 保存、异常与恢复

`decisions.json` 保存本批绑定清单哈希、版本、当前结论及变更事件；`dataset_manifest.json` 仅列当前通过样本。重复请求不重复导出，多标签页版本冲突会要求刷新。OS 锁保证同一原数据集/确认目录只能有一个服务拥有写权限；重开第二个服务不会回滚运行中的保存。

替换前先备份，目标盘上分阶段准备，写入事务日志后再替换目录和审核文件；成功提交才返回通过回执。E/F 盘分别在目标旁准备目录。保存中断后重启会根据日志回滚未提交事务或完成已提交清理。Windows 文件占用时保留日志并阻止新写入；关闭占用程序后，可在页面点击“恢复未完成保存”。原文件或已通过样本被其他程序修改会拒绝同步，避免覆盖外部改动。

播放原片使用冻结副本；已通过的视频使用内容哈希命名的不可变媒体副本，避免播放占用阻止数据替换。接口仅绑定 127.0.0.1，限制 Host/Origin，写接口使用本次服务令牌；没有外网发布。服务不可用时播放和筛选仍可用，保存按钮禁用并显示重新连接入口。

本批审核期间不要重新生成/覆盖 combined_review_manifest.json。改变本批清单会拒绝复用已有确认目录；需要新的批次目录。旧 v6 技术验证报告仅描述当时的冻结筛选包，人工回写后不要再把 E 目录视为未变的 v6 原始输入。

候选修订部署顺序为：停止本批服务 → 使用拥有源/确认独占锁的 ReviewStore 发布修订 → 通过 serve_behavior_review.py 重启服务，重新生成包含新修订 SHA 的页面。运行中的服务持有旧候选目录，不能跳过重启；不能在另一服务仍运行时发布。
