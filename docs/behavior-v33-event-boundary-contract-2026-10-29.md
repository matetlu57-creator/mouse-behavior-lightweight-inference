# V33：识别事件与裁剪边界统一

本次以人工清洗的 605 段数据为参考。用户在本次会话确认：片段首末帧已经人工精裁，因此 annotation 的本地含末帧范围是本次边界比较的标准。五类参考样本共 148 段：接近 46、一起 4、扎堆 66、社会聚集 7、孤立 25。

## 已确认的问题与处理

| 问题 | 影响 | 处理 |
|---|---|---|
| manifest 的 start/end 是事件范围，frame_count 却可能包含播放上下文 | 仅看总表会把准备、接触或收尾当成目标行为 | 新增统一 EventBoundary，manifest v2 同时记录真实事件、播放裁剪、偏移及两种帧数；旧字段保留兼容 |
| 接近按主动/被动角色拆段后只检查时长和路径 | 子段末帧可能已经不满足原事件的结束几何 | 拆段和跨窗口合并后都调用同一条 Approach 规则，重新检查该方向的起止、路径与无接触几何 |
| 社会聚集被 core 窗口截成已经成群的后半段 | 片段保留密集状态，却丢失行动鼠形成群体的前缀 | 与接近、散开一样保留完整合格父过程；不同确认终点的形成过程不直接融合 |
| 扎堆把后加入成员写回早期事件 | 指定成员集尚未成立时已经开始裁剪 | 以所选成员的首次支持、末次观测或经验证驻留收紧边界；每个输出段重新满足 5 秒 |
| 孤立识别允许累计有效比较时间，裁剪却要求每个检测连续小段超过 10 秒 | 同一真实孤立过程被检测缺失切碎，最终没有片段 | 保留首末有效比较之间的过程范围，真实比较支持与未知区间分别保存；有效时间本身仍须严格超过 10 秒 |
| 已批准的重复比较对象只进入旧统计，没有正常推理入口 | 原本已确认的同鼠重复框仍可能否决孤立 | 显式加载 source-bound review；核对样本、视频/轨迹 SHA 与缓存的每帧 ID、框、关键点，只排除指定比较边 |

这些修复不补检测框、关键点或身份，不自动把其他近距离 ID 对视为重复，不改动原始数据。

## 当前时间下限

| 行为 | 事件或有效时间下限 | 关键边界要求 |
|---|---|---|
| 接近 | 严格 >1 秒；行动鼠实际观测路径 >=10 cm | 主动鼠方向单独验收；与目标鼠的已知身体分离；拆段后的末帧不能继承父事件几何 |
| 一起 | >=1 秒 | 仍要求距离与双方速度条件；保留无接触相伴的既有定义，接触几何单独标示 |
| 扎堆 | >=5 秒 | 修正所选成员进入、离开的边界；保留原来授权的遮挡/驻留处理，避免把“每帧全员都有轨迹”作为新条件 |
| 社会聚集 | >=0.5 秒；行动鼠实际路径严格 >10 cm | 保留原识别条件与接近成群前缀；新收尾试验未通过人工边界对照，没有启用 |
| 孤立 | 有效最近邻比较时间严格 >10 秒 | 整个绑定源范围内，目标所有有效比较距离均严格 >20 cm；未知帧不估计距离、不计有效时间 |

接近参考集有 22/46 段不满足当前严格 >1 秒门。它们保留在主分母并单列，不删除、不扩展、不降低时长门槛。

孤立的时间不是“视频播放超过 10 秒即可”。`canonical_support_frame_intervals` 必须提供超过 10 秒的真实有限最近邻比较；`unknown_comparison_frame_intervals` 保存没有比较依据的原始帧。一个实测 <=20 cm 的帧仍否决整个绑定源范围内该目标的孤立，不能只截后面的远离阶段来恢复。

## 一个边界对象贯穿三个 JSON 和总表

所有机器范围统一为 source-video 的半开区间 `[start,end)`：

```json
{
  "source_event_half_open": {"start": 27, "end": 61},
  "playback_crop_half_open": {"start": 19, "end": 61},
  "event_offset_in_playback_half_open": {"start": 8, "end": 42},
  "event_frame_count": 34,
  "playback_frame_count": 42,
  "context_before_frames": 8,
  "context_after_frames": 0,
  "playback_scope": "event_with_leading_context",
  "qualification_basis": "source_event_half_open_only"
}
```

正常 CLI 默认上下文为 0：播放裁剪就是事件本身。显式选择上下文时，它只用于审核，不参与行为资格。Approach 始终没有尾部上下文。

`annotation.frame_range.end` 和 `metadata.source.end_frame` 继续保留历史的含末帧表示，避免破坏现有标注软件；新的 `boundary` 对象、manifest JSON/CSV 已将坐标含义写全，消费者不得自行混用。

每个裁剪包仍为 `clip.mp4`、`annotation.json`、`metadata.json`、`tracks.json`；tracks 的 frame/time 从 0 开始，保留全部原始可见检测。

## 正式入口

```powershell
python scripts/run_canonical_behavior_video.py `
  --video <source.mp4> --pose-cache <verified-cache-directory> `
  --source-receipt <source-and-model-receipt.json> `
  --config configs/default.yaml --output <new-output-directory> `
  --mode clips --original-video --clip-context-seconds 0
```

已审核比较对象需要三个显式参数一起给出：

```powershell
--comparison-reviews <scoped-reviews.json> `
--comparison-sample-id <exact-sample-id> `
--comparison-tracks <original-standardized-tracks.json>
```

该入口不会把整个旧样本的审核自动应用到长视频。视频或轨迹 SHA 不同、缓存中的 ID/框/关键点不同、样本不匹配或审核 JSON 键重复，均拒绝。对已持久化事件重新渲染时也不能偷偷替换比较政策，必须重新推理。

历史 `temporal_screen`、展示窗口、V32 重筛脚本不等同于本入口的新完整推理。旧交付物保留为审计材料，不代表可以混用其事件、播放范围或版本结果。

## 已拒绝的试验

1. 要求扎堆每一帧全员轨迹支持，使参考集覆盖命中从 37/66 降到 14/66；核对真实稳定鼠堆后未采用。最终只修正进入/离开的边界，保留既有遮挡语义。
2. 社会聚集自动在首次确认或后续最后趋向动作处收尾，使精裁参考集覆盖命中从 3/7 降到 1/7；未采用。该行为的自动精确收尾仍是已知问题，不能把格式检查或单元测试通过当成它已解决。

## 验证与解释范围

- 冻结修改前的工作树源码、同一配置与源视频标定，前后比较相同 148 段。
- 生成候选使用所有观测 visual track IDs；人工行为和 ID 只用于之后的评分和示例选择。
- 评分同时报告完整 ID 集合的候选存在、>=50% 人工区间覆盖、IoU 和起止偏差。它不是旧 755 样本 A2，也不改写含人工补充的 A1。
- 数据为人工正例参考集，本次结果不能推出长视频的全部误报率；visual track ID 也不等同于跨片段稳定动物身份。
- 普通推理入口有真实缓存绑定集成测试；一段真实参考视频经过 3 个 core 窗口、合并、原画面裁剪与完整解码，边界/帧数一致。
- 参考数据和旧结果保持不变。代码检查、完整回归结果及各输出哈希由本次独立质量记录保存。

原数据位置、各轮试验、最终采纳对照和复核样例的具体路径由本次本地交付索引给出。
